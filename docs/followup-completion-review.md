## VS Code 的具体起步堵点

用户截图显示 cmd 执行 `./hello.exe` 失败。Go第1课原命令错误已修正：PowerShell用 `.\hello.exe`，cmd用 `hello.exe` 或 `.\hello.exe`，macOS/Linux用 `./hello`。查看目录/文件命令也分终端说明，避免cmd用户照抄pwd/ls。

[VS Code教程](tutorials/vscode.md) 第8–13节补齐 Go Team 扩展、gopls/dlv 安装、独立工作区、四份完整 JSON、任务菜单、编译快捷键、F5断点/变量/单步与输入程序。另针对真实截图的 `The "dlv" command is not available` 解释安装按钮、工具安装命令面板、下载错误、工具路径定位；fmt红线要求先读取完整诊断，不凭截图猜源码错误。

四张图片是独立教程环境中的真实VS Code窗口捕获，展示扩展、工具安装入口、settings和任务搜索；并非合成界面，也不声称展示了成功的F5暂停。任务搜索图默认高亮相似命令，正文与图注明确按准确名称选择Tasks: Run Task。用户按Escape停止界面操作后，不再操作原生界面。实际执行与调试验证通过独立CLI/DAP完成，细节见 [配置独立审核](vscode-setup-peer-review.md) 和 [网页图文审核](vscode-site-peer-review.md)。

[Go起步源码包](../assets/downloads/vscode-go-starter.zip) 含main.go、go.mod、README与`.vscode`四个配置。ZIP从规范配置源生成，不在资料根目录建模块，不修改用户现有工程或全局编辑器设置。完整JSON与源码可复制，输出块不提供误导的命令复制按钮；本地截图加载仅允许站内教程图片路径，其他Markdown图片仍不发起外部请求。

## 验证边界

仓库属性补上Shell/TypeScript/SQL/YAML等源码的LF约定，避免Windows新克隆后把容器挂载的`.sh`转成CRLF而无法执行。原教材的`-text`保留规则仍优先，不借此改原始资料；源码ZIP也统一LF。属性核对不被当作实际容器启动验收。

Windows上真实运行的结果不能冒充Mac/Linux实机验证。Compose配置已解析，当前审核环境未启动Docker守护进程；云端TLS、远程CI和真实生产服务器没有冒充实跑。生产认证的HTTPS/数据持久化/限速与恢复条件写在对应README；内存教学模式明确不持久化。Vue提供等价组件分支，完整capstone选React实现，并不声称两框架全量项目均已实现。静态学习网站只提供教材与下载，不在线执行后端/数据库，也不生成AI模型回复。
