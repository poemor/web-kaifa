## 必须修正的问题

### 1. 表单主例的“清空本地输入”实际失效

- 位置：`docs/knowledge/web/web-forms.md` 的完整 HTML；修复前按钮为 `id="reset"`，监听内调用 `form.reset()`。
- 复现：按原文保存完整 HTML，填“小林”与 `lin@example.com`，检查通过；把姓名改为“小张”，再点“清空本地输入”。
- 实际：姓名仍为“小张”，Console 报 `TypeError: form.reset is not a function`。没有得到文中要求的清空反馈与起点焦点。
- 原因：表单控件的 id/name 会参与表单命名属性访问；`reset` 控件遮蔽了原生方法。这个边界也由 [MDN reset 文档](https://developer.mozilla.org/en-US/docs/Web/API/HTMLFormElement/reset) 明确说明。
- 建议：控件改为 `reset-input` 等非方法名，同步事件选择器；加入成功后清空、错误后清空、输入撤销旧结果、焦点归还与无网络提交检查。原有测试只点成功提交和空格校验，没有走这个分支。

### 2. 第 12 课旧表单与“只本地检查”的教学承诺冲突

- 位置：发布版 `curriculum.js` 中 `web-12` 的 `starterCode` 和 `sourceMarkdown`。
- 旧例子使用 `<form action="#" method="get">`，按钮为 submit，同时文字解释“暂不发送数据”“当前没有服务器”。
- 实际证据：在隔离本地 HTTP 页面填写虚构输入并提交，服务器收到 `/old-web12/?name=教学测试姓名&message=教学测试留言`，地址栏也出现 query。
- 影响：HTTP 模式下数据仍会随 GET 请求传到提供网页的服务器；没有业务后台不等于没有请求。零基础用户照做会得到与详细知识主题不同的行为。
- 建议：用补充课程适配覆盖旧讲义与起点，保持原材料不动；显式阻止默认提交，给出本地校验和未提交说明，并在 Network 验证没有新的报名请求。表单 GET 行为依据见 [MDN form 文档](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/form)。

### 3. 请求课缺少真正的首次 HTTP 环境准备路径

- 位置：`web-fetch.md` 的运行步骤与 `docs/tutorials/web-environment.md` 第 6 节。
- 请求课要求 Python 并让未安装者返回起步教程；起步教程仅给“如果已经安装 Python 3”命令，并让没有命令者“需要服务器时再按课程准备环境”。首次使用者会在两页之间循环，仍不知道从哪里下载、如何安装和验证。
- 请求课统一给 `python -m http.server ...`，但起步教程对 macOS/Linux 给 `python3`，没有在请求课提供同样的系统分支。
- 建议：补充官方安装与版本验证，逐系统给出同一套启动步骤，说明运行所在目录、地址、端口冲突和 Ctrl+C；把请求课连到具体步骤。查证来源：[Python Windows 安装说明](https://docs.python.org/3/using/windows.html)、[Python macOS 安装说明](https://docs.python.org/3/using/mac.html)。

## 讲解仍有断层的地方

### 4. JavaScript 主例中的关键语法没有逐步解释

`web-js` 的计算原理、数组/filter/map 和输入边界解释已相当完整，但示例直接使用箭头函数、回调、`===`、三元表达式与模板字符串；正文尚未把它们拆开。零基础读者能复制运行，却难以解释 `items.filter(item=>...)` 为什么会逐项处理，以及 `titles.length ? ... : ...` 如何选择反馈。后续阶段又将作用域、回调与空值列为掌握点，现有一句解释仍不足以支撑独立改写。

建议补普通函数与箭头函数的等价例子，逐次跟踪 filter 输入/布尔值/输出，分清赋值与严格比较，把三元改写为 if，解释 `${...}`、let/const 以及 null/undefined 的最小例子。不要只是增加更多术语。

### 5. 第 10 课的相对单位与 clamp 缺少可以计算的依据

第 10 课代码使用 `clamp(28px, 5vw, 44px)`；详细 CSS/响应式主题虽然使用 rem、vw、百分比与 min/max，却没有明确说明各自参照物及 clamp 三个参数怎样选值。学生无法预测为什么某个宽度显示某个字号。

建议给出根字号 16px 时 1rem/2rem 的例子、320px 视口下 5vw=16px，以及 320/768/1280px 下该 clamp 的 28/38.4/44px 对照。强调用户根字号可能变化、百分比参照物随属性而不同，避免把相对单位等同于万能响应式。
