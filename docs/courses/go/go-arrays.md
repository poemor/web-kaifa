# 数组与下标

用固定长度数组保存三个分数，读取和修改一项。

## 数组与下标是什么意思

数组把多个同类型值放在固定长度的容器里。[3]int表示3个整数。下标从0开始，最后一个下标是长度减1；数组长度属于类型的一部分。

## 多个同类型值放到一组里

前面用一个变量放一个分数。现在用数组放三个整数，`[3]int` 表示长度为 3、元素类型为 int；花括号里的三个值按顺序初始化。**下标是位置编号，从 0 开始；长度是元素总数，两者不同。**

| 日常称呼 | 代码下标 | 初始分数 |
| --- | --- | --- |
| 第一项 | `scores[0]` | 60 |
| 第二项 | `scores[1]` | 80 |
| 第三项 | `scores[2]` | 100 |

`[3]int` 和 `[4]int` 是不同的数组类型，不能只因为里面都有整数就直接赋值给彼此。没有写出初值的整数元素会得到零值 0。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	// [3]int 是固定三个整数；花括号按顺序提供初值。
	scores := [3]int{60, 80, 100}
	fmt.Println(scores[0])              // 下标 0 是第一项，不是“没有项”。
	scores[1] = 90                      // 只更新第二项，不改变数组长度。
	fmt.Println(scores[1], len(scores)) // len 数元素个数，结果仍是 3。
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
60
90 3
```

## 逐步读懂这个例子

数组有3项，下标依次是0、1、2。scores[1]=90更新第二项，不改变长度。len(scores)返回元素个数，而不是最后一个下标。整个数组赋值会复制各项的值。

`scores[1] = 90` 发生之后，整组数据是 `[60 90 100]`，第一项仍为 60，长度仍为 3。`fmt.Println(scores[1], len(scores))` 输出两个值，中间有空格，读成“第二项 90、总共 3 项”。

赋值 `other := scores` 得到包含三个整数副本的另一个数组；改 `other[0]` 不会改 scores[0]。下一课的切片有不同的共享规则，不能把两者混在一起。

## 自己改一处再运行

把第三项改成95，打印第三项；说明为什么scores[3]不是第三项。

### 参考答案

第三项是scores[2]，输出95。下标3越过长度为3的数组。

## 本节容易混淆的地方

常量越界可以在编译时被发现，变量下标越界会在运行时引发panic。访问前核对范围。

## 检查访问范围

打印并修改第三项时使用下标 2。若直接写 `scores[3]`，编译器能看出这个固定下标越界，会拒绝运行。若下标来自变量且运行时越界，会出现 panic，也就是程序因无法继续安全执行而报错终止。

恢复范围后重新运行。能写出“有效下标满足 0 ≤ 下标 < len(scores)”并解释最后一个下标为何是 2，才算分清位置和数量。

## 合上参考，独立整理四项测量值

从空白 main.go 建立固定四项的整数测量记录，初值依次为11、12、13、14。自己声明数组，先读取第四项，再把第四项更新成24，输出数组长度和整组数据。

随后把更新后的数组赋给另一个变量，仅把副本第一项改成99。预期：第四项原为14，长度始终为4；原数组最后是 `[11 12 13 24]`，副本是 `[99 12 13 24]`。

**先写出第四项和末项以外位置的下标，再访问；四项数据不意味着有下标4。** 用自己的程序解释为何修改副本第一项不改原数组。

### 参考答案

第四项的下标为3。固定数组赋值复制这里的四个整数，因此两个变量之后可独立修改。检查长度与两组最终数据，就能发现误把下标、长度或副本混在一起的问题。
