# CRUD 接口约定与内存实现

将方法、路径、输入和结果写成合同，再追踪一条记录的创建、读取、修改与删除。

## API 是给调用者使用的约定

API是应用程序接口，这里指客户端通过HTTP调用的一组入口，不是某个Go关键词。CRUD代表创建、读取、更新、删除。**先约定输入和结果，再实现；端口启动成功不等于四种操作都正确。**

本项目管理活动，每条活动有id、title、location。它不直接沿用练习表practice_problems。客户端送JSON，服务器校验、更新MemoryStore，再回JSON；MemoryStore是内存存储，服务重启会恢复种子，不保存用户新增数据。

## 这份工程的最小合同

| 操作 | 方法和路径 | 正常结果 | 关键失败 |
| --- | --- | --- | --- |
| 创建 | POST /api/events | 201与新活动 | 空标题/未知字段400，大小413，类型415 |
| 列表 | GET /api/events | 200与数组 | limit/offset非法400 |
| 详情 | GET /api/events/{id} | 200与活动 | 非法id400，不存在404 |
| 更新 | PATCH /api/events/{id} | 200与更新活动 | 空修改/非法字段400，不存在404 |
| 删除 | DELETE /api/events/{id} | 204，无正文 | 不存在404 |

`{id}`是路径参数占位，例如 `/api/events/8`。它与问号后的查询参数不同。客户端应使用创建响应的实际id，不能以为永远是1。列表使用limit/offset，不自动识别page。错误JSON含 `error.code` 和 `error.message`，业务合同与HTTP状态一起检查。

## 准备并启动完整工程

下载 [Go内存API](assets/downloads/web-followup-08.zip)，解压，用VS Code打开followup-08目录，它已经有独立go.mod。运行go version，确认工具链满足go.mod声明；依README先验证：

```sh
go vet ./...
go test -v ./...
go run .
```

保留服务终端，浏览器打开 `http://127.0.0.1:8768/`。网页提供新增、筛选和操作入口，F12的Network可查看请求与响应。按Ctrl+C停止。若端口占用，停止自己旧服务；改APP_ADDR后浏览器地址也相应改变。

**先只跟踪创建，不要求一次读懂全部代码。** 文件导航：main.go组装服务器；api.go处理HTTP；store.go保存内存记录；api_test.go验证合同；web/app.js是浏览器交互。Go不执行浏览器JavaScript。

## 一次 POST 的数据流

1. 浏览器发送JSON正文 `{"title":"Go读书会","location":"A教室"}`，请求头Content-Type为application/json。
2. api.go里的save识别创建操作，decodeJSON检查类型、大小、未知字段和单个JSON值。
3. 标题去首尾空白后必须1–100字符，地点最多100字符。验证失败先返回400，不调用Create。
4. store.go的Create取得互斥保护，分配id、加入内存，再返回保存后的值。HTTP可并发，因此所有共享访问需要同一保护规则。
5. Handler写201与JSON，前端确认成功才把结果显示出来。失败不得先把“已保存”加入页面。

## PATCH 的“没给”不是“清空”

PATCH修改一部分。Go字符串零值为空，单用string字段会混淆“请求没给location”和“请求明确想清空”。本项目输入用指针表示可选字段：nil表示没提供，非nil即使指向空字符串也可表达清空地点。title不能被清空。

```json
{"location":""}
```

这表示只清空地点，标题应保留。项目把null按未提供处理，至少提供title/location一项才是有效修改。**输入模型要表达合同，不能用零值猜客户端意图。** 具体指针写法回看 [指针](#/learn/go/go-pointers)。

## 先预测，再验证完整生命周期

新建自己的虚构活动，记创建响应id；读取详情；只改地点；重新读取确认标题未变；删除；再读同id应404。用Network记录201→200→200→204→404，不能只看按钮提示。

再提交纯空格标题、数组标题、未知role。应400且列表未新增；错误JSON也不改变存储。独立发送请求可按 [第08阶段curl文件步骤](#/followup/web/8) 做，Windows使用curl.exe，复杂JSON先存文件，避免Shell引号造成误判。

重启Go再查询新id：它应不再属于刚才保存的数据，原种子恢复。这是内存模式的已知限制，不是数据库损坏。没有登录、权限或数据库，服务只面向本机教学。

### 参考答案

若创建失败却显示新活动，是前端提前宣告成功；若只改地点却丢标题，是PATCH未提供与零值混淆；若204有正文，合同或实现不一致。

## 独立变式

配套工程已经支持 q 标题包含筛选，不把它当作待新增功能。先独立补 q 的空关键词、命中、不命中三组测试；然后在自己的 CRUD 副本中新增 `location` 查询参数，按地点完全相等筛选，空参数不筛选。自己决定数据流程，先筛选再分页；本工程列表响应仍是数组，不额外要求尚未约定的统计字段。

在只含“教室A、教室B、教室A”这三条活动的隔离测试数据中验收，不含工程默认种子：查教室A得到2条，查不存在地点得到0条，不提供 location 得到3条；同时确认 q 与 location 一起使用时都满足。如果在原服务里额外新建三条，未筛选列表还会包含原有种子，不能照搬3条的预期。再把一个输入校验断言故意改成“错误输入应201”，测试必须失败，恢复后通过。
