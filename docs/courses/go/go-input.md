# 从终端读取一行输入

读取一整行文字，并检查读取错误。

## 从终端读取一行输入是什么意思

os.Stdin提供终端输入。bufio.Scanner默认按行读取；Scan返回是否读到一行，Text返回该行，Err检查异常。Enter提交输入；输入结束与空行是不同情况。

## 程序等待的是你提交的一行

前面的变量初值写在源码里。现在程序运行后从终端取得数据。标准输入 os.Stdin 是程序默认读取输入的通道；Scanner 是按规则切分输入的读取工具，默认以一行为一项。

**运行命令后，接着在终端输入文字并按 Enter；等待输入没有输出，并不表示程序死掉。** 本例只读取一行，打印后就结束；想输入第二行，要重新运行一次。

Scan 返回 bool，告诉你有没有读到一行；Text 返回刚读到的这一行，不包括末尾 Enter 对应的换行；Err 返回读取异常。**必须先执行 Scan，成功后 Text 才代表这次读到的一行。** 调用 Scan 后可以检查 Err；尤其 Scan 为 false 时，要靠 Err 区分正常结束与读取异常。Err 不是只能放在 Text 之后检查，新程序也可以先排除错误再使用文字。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import (
	"bufio"
	"fmt"
	"os"
)

func main() {
	// os.Stdin 是标准输入；这里交给 Scanner 按行读取。
	scanner := bufio.NewScanner(os.Stdin)
	if scanner.Scan() { // 等到一行输入或输入结束，再返回是否读到一行。
		fmt.Println("读到：" + scanner.Text()) // Text 不包含末尾的换行符。
	}
	// 正常输入结束不算读取错误；真正的异常由 Err 返回。
	err := scanner.Err()
	if err != nil {
		fmt.Println(err)
	}
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
读到：hello world
```

## 逐步读懂这个例子

程序等待你输入hello world并按Enter，输出读到：hello world。空格被保留。本例没有主动提示文字，等待输入与卡死不同。

启动 `go run .` 后还没有本课输出。在终端输入 `hello world` 并按 Enter，Scan 得到 true，Text 得到保留空格的 hello world，输出“读到：hello world”，程序结束。

按 Enter 提交一个空行时，仍然读到了一行，因此输出“读到：”。输入结束且没有任何一行时，Scan 才会返回 false；这是“没数据”，和“读到了空文字”不同。正常输入结束不必产生 err。

## 自己改一处再运行

输入带空格的称呼，再输入空行，记录程序收到的内容。

### 参考答案

空行仍是一行，Text为空字符串；输入结束且没有一行时Scan为false。

## 本节容易混淆的地方

Scanner有默认行大小上限。取消用Ctrl+C，不能假设任意大文本都可直接读取。

## 空行与结束输入分别验证

重新运行后直接按 Enter，核对“读到：”。再重新运行，在 Windows 终端用 Ctrl+Z 后按 Enter（部分终端会有不同表现），或 macOS/Linux 用 Ctrl+D 结束输入，观察没有一行可读时程序不打印前缀。要中止当前程序可用 Ctrl+C。

Scanner 默认有约 64 KiB 的单项缓冲限制；本课只读短行。遇到大文本要配置大小并保留 Err 检查，不能把 Scan 的 false 一概当作正常结束。

## 实际走一次读取错误分支

为了不用手工输入几万字，临时在 `scanner := bufio.NewScanner(os.Stdin)` 后、第一次 Scan 之前加一行：

```go
// 初始缓冲空间16字节，最大32字节；故意缩小，只用于本次错误实验。
scanner.Buffer(make([]byte, 16), 32)
```

Buffer 的第一个参数提供初始字节空间，第二个参数给出本次扫描单项的最大缓冲大小。运行后输入一行 40 个英文 `a` 再按 Enter，超过 32 字节：Scan 返回 false，不打印“读到：”，Err 分支应打印 `bufio.Scanner: token too long`。

**空输入结束和读取失败都可能让 Scan 返回 false，必须继续看 Err 才能区分。** 删去这行临时限制，再输入 `hello world`，确认恢复正常。实际业务应按输入规则设置合理上限，不应为绕过错误直接忽略 Err。

## 合上参考，独立写称呼问候

从空白 main.go 自己建立按行读取终端的Scanner，只处理一行称呼，区分“读到非空文字”“读到空行”“没有一行数据”和“读取异常”。先用Scan取得是否有行，再检查Err；只有确认不是读取失败，才使用Text或判断正常结束。

| 输入路径 | 输出要求 |
| --- | --- |
| 输入“阿青”后Enter | 你好，阿青 |
| 直接Enter提交空行 | 称呼为空 |
| 未输入一行就按本节说明结束输入 | 没有输入 |
| 按本节临时32字节上限，输入40个a | 显示读取错误及token too long，不显示问候或“没有输入” |

先预测，再逐项运行自己的程序。异常实验结束后删去临时上限，用“阿青”再次验证正常路径。**空行、正常结束和读取失败不能共用一个含糊提示。**

### 参考答案

Scan结果说明有没有一行，Err说明无行是否由异常造成；只有err为nil时再区分正常结束与行内容。空行的Text是空字符串，它仍不同于没有一行输入。保留自己的四组输出与恢复结果。
