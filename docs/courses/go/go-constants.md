# 常量与变量的区别

用 const 表达固定规则，用变量表达会变化的数量。

## 常量与变量的区别是什么意思

常量使用 const 声明，在程序里不能被重新赋值。例如及格线是本练习固定规则；某次考试分数是变量。先用简单常量，枚举和 iota 留到需要时再查。

## 规则固定，数据可变

**常量的值在这份程序中固定，变量的值允许被赋值更新。** `passScore` 表达本练习约定的及格线；`score` 表达某一次成绩。把及格线起一个名字，后面的比较就不必重复猜测数字 60 代表什么。

这一节第一次用到 `>=`，读成“大于或等于”：`75 >= 60` 为 `true`，`59 >= 60` 为 `false`。它只产生一个判断结果，不修改成绩，也不输出“及格”文字；下一课学习全部常用运算符，条件课再根据结果选择动作。

## 先运行一个小例子

在已初始化的独立 Go 练习目录中，把下面完整代码保存为 main.go。本节替换原文件，不在文件末尾追加另一份 main 函数。

```go
package main

import "fmt"

func main() {
	// 及格线是本练习固定的规则，const 不允许运行中重新赋值。
	const passScore = 60
	score := 75 // 本次成绩是变量，可以在源码中改成其他分数再运行。
	fmt.Println(passScore)
	// >= 询问“成绩是否大于或等于及格线”，结果是布尔值。
	fmt.Println(score >= passScore)
}
```

在这个目录的终端运行：

```sh
go run .
```

预期输出：

```output
60
true
```

## 逐步读懂这个例子

passScore 固定为 60。score 是 75。`>=` 比较左边是否大于或等于右边，结果是布尔值 true。这个结果可以打印，也可以在后面的条件语句里使用。

第一行输出固定规则 60。第二行先读取 score 和 passScore，再做比较，最后把比较结果交给 Println。把成绩改成 59，规则仍为 60；把常量声明中的 60 改成 70 并重新运行，则是改写了程序的规则。

`const course = "Go"` 也可声明文字常量。常量不是“绝对永远不能改的文件”，它禁止的是在程序运行逻辑里给这个常量再赋值。

## 自己改一处再运行

只把 score 改成 59，再运行；然后改成 60。

### 参考答案

59 时第二行是 false，60 时是 true，边界包含 60。

## 本节容易混淆的地方

不要尝试用 passScore = 70 修改常量。规则变了应修改声明并重新运行。

## 观察不能重新赋值的含义

在常量声明后增加 `passScore = 70`，保存运行，应看到不能赋值给常量的编译错误。删除这行，再把声明本身改为 `const passScore = 70`，程序可以运行。这两次都实际验证后，用一句话说明区别。

成绩依次用 59、60、61；预期判断结果依次是 false、true、true。**包含临界点的实验能够检验 `>=` 是否写对。**

## 合上参考，区分自己的规则和数据

从空白 main.go 表示“固定目标为 30 分钟，本次计划为 29 分钟”。自己命名目标与计划，选择常量或变量来保存它们，并各打印一行。暂时不写分支、循环或复杂比较，本题只验收声明选择。

将本次计划依次设为 29、30、31，分别运行；第一行应始终为 30，第二行分别为 29、30、31。再试在运行逻辑里给目标重新赋值，确认编译拒绝；删除错误赋值，把目标声明本身改为 40，重新运行才会显示新目标。

**独立说明“固定规则”与“允许更新的数据”，不要只沿用 passScore 和 score。**

### 参考答案

固定目标用 const，本次计划用变量。编辑常量声明后重跑是在改程序规则；在程序运行逻辑里重新给常量赋值则被禁止。本题不需要尚未学习的控制流程。
