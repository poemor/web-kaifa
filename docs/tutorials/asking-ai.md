# 遇到问题，怎样问 AI 才能继续动手

一次好提问，让别人能看懂你在哪一步、想看到什么、实际发生了什么。你的目标是学会验证原因，而不只是拿到一段新代码。下面是本仓库编写的练习方法，不保证模型每次判断正确。

## 1. 先花一分钟收集证据

1. 保存文件，再复现一次问题。说明是点击了什么，还是运行了哪条命令。
2. 写下**预期结果**和**实际结果**，分开写。
3. 复制相关错误原文、文件名和行号。截图可以补充界面，错误文字和代码尽量用文本提供。
4. 截取能复现问题的最小相关代码；多文件问题写清每个文件名和相互引用。
5. 记录已经试过的一到两步以及各自结果，避免反复得到相同建议。

**不知道证据在哪？** 系统版本在系统设置的“关于”里，Go 版本在终端执行 `go version`，当前目录执行 `pwd`；VS Code 版本在 Help → About（帮助 → 关于），Mac 在 Code → About Visual Studio Code。Web 问题补浏览器名称与地址栏是 `file:` 还是 `http:`；版本确实没查到就写“暂未查到”，不要猜。

终端里用鼠标选中相关错误后复制：Windows 通常 `Ctrl+C`，Mac 为 `Cmd+C`，Linux 为 `Ctrl+Shift+C`。**先选中文字**；没有选区时 `Ctrl+C` 常用于停止程序。复制自己输入的命令和对应输出，不只截最后一行。若键盘复制不起作用，用终端右键菜单的 Copy（复制）。文件中的代码在编辑区选择后复制，保留文件名。

发出前移除密码、令牌、Cookie、个人资料和不相关项目内容；保留错误类型与必要上下文。如果不确定某段代码是否相关，就说明“我不确定是否相关”，不要编造已运行的结果。

## 2. 六项提问骨架

```text
我正在做：具体课程、文件或一个小目标。
环境：操作系统、编辑器、语言/工具版本、终端类型、当前相对目录。
预期：我执行什么后，应该看到什么。
实际：完整报错或实际输出；没有报错也写清现象。
相关代码：标明文件名，保留能复现问题的最小片段。
已经试过：做法 → 结果；没有尝试就如实写“还没尝试”。

请先指出缺少的证据，再给一个最可能且可验证的原因。
一次只给一个检查步骤，说明在哪里执行、预期看到什么。
先给线索，不直接重写整个项目；没有验证过的判断请说明。
```

零基础可再加一句：“新术语先解释；分清哪些内容写进文件，哪些命令在终端输入。”已有编程基础者可补接口契约、最小复现与版本差异。

## 3. 从模糊问题改成可排查的问题

**模糊问法**：“Go 跑不了，帮我修好。”

**教学示例，不代表你电脑上的实际情况**：

```text
目标：运行 exercises/go/setup-check 里的 main.go。
环境：Windows，VS Code 的 PowerShell；go version 能输出版本信息。
我在仓库根目录运行 go run .，预期打印一句学习目标。
实际：提示 go.mod file not found。
文件：go.mod 和 main.go 都在 exercises/go/setup-check 中。
已试过：保存 main.go 再运行，报错相同。
请先教我确认当前目录，不要重新生成整个项目或在根目录初始化模块。
```

这份提问提供了目标、环境、命令、目录关系和实际结果。下一步应先验证目录是否正确；仍要以你电脑上的输出为准。

**Web 示例**：“我修改了 `index.html` 的 h1 并保存，预期浏览器显示新标题，实际仍是旧标题。我复制过两份文件夹，已刷新一次。请先指导我核对浏览器地址与文件路径，只检查这一点。”

## 4. 完整例子：程序没有新输出，该怎么问

假设你在 Go 教程里已经构建了 hello 程序，后来修改并保存源码，却只启动了旧的可执行文件。这里先给一份**教学场景**，实际提问时要用你自己的命令和观察替换，不能把它冒充运行记录：

```text
我在学 Go 的编译和运行，想修改终端显示的句子。
环境：Windows，VS Code，PowerShell。
当前目录：exercises/go/setup-check，里面有 main.go、go.mod、hello.exe。

我先执行了 go build -o hello.exe .，再执行 .\hello.exe，输出“第一步：保存文件”。
后来把 main.go 的第一句改成“我改好了”，按了 Ctrl+S。
然后我只执行 .\hello.exe，预期显示“我改好了”，实际仍是“第一步：保存文件”。
我已试过重新保存和再运行 exe，结果不变。

请先解释源文件与可执行文件的关系，再给一条验证命令。
说明命令在 VS Code 哪个位置输入、成功后应该看到什么。
我现在只想理解这一步，不要替我配置一套新的项目。
```

为什么这份问题有用？它把“我改过什么”和“我执行过什么”分开了。对方能比较：源码更新了，但构建是否重新执行？如果只说“VS Code 没反应”，别人无法判断你是在看编辑器、终端还是浏览器，也可能误让你重装环境。

接下来无论建议来自 AI、老师还是同学，都做同一件事：在终端执行你已经理解的那一步，保存实际结果。如果建议重新构建，构建命令没有输出学习目标不代表失败；还要运行新的 exe 才能看到程序打印。这个判断需要你自己观察，不能让 AI 替你声称成功。

反馈可以这样写，把方括号替换成真实结果：

```text
我在原目录执行了【完整命令】，终端显示【原文，或没有输出且回到提示符】。
随后执行【启动命令】，看到【实际输出】。
现在与预期【一致 / 不一致】。
我的理解是【用自己的话说明原因】。请检查我的理解，而不是再贴一遍完整程序。
```

Web 也可以照这个结构排查：把“源码/可执行程序/重新编译”换成“编辑器文件/浏览器页面/保存并刷新”，再核对浏览器打开的路径。不同问题需要不同证据，模板是帮你组织信息，不是把所有字段堆得越长越好。

## 5. 看不懂代码时，怎样让 AI 真正教你

排错和学习概念不是同一种提问。排错要给现象与复现步骤；学习概念可以指出“哪一行不懂”和“目前知道什么”。例如，不要只问“详细解释 Go”，把目标缩小到刚才真实使用的语句：

```text
我刚能运行自己的 Go 程序，但不明白 minutes := 20 和 total := minutes * days。
我知道数字相乘，不知道“声明变量”和“赋值”是什么。
请先用这两行代码解释，每个符号各是什么意思；给出完整可运行的小例子。
告诉我应该替换哪个文件的哪一段，运行什么命令，预期输出是什么。
最后让我把 days 从 3 改成 5，先等我预测结果，再解释。
不要在这个问题里引入数据库、框架和指针。
```

如果它给了太长的答案，可以继续要求：“先只讲 `:=`，给一个正确例子和一个常见错误，等我动手后再讲下一点。”如果它只给答案却没解释，可以问：“为什么这样改会有效？如果我不改会发生什么？我用哪一步实验能区分两种解释？”

**判断自己有没有学会**：暂时合上回答，换一个变量名或一句文字，独立保存、运行、解释结果。只会复制得到相同输出，说明你已经走通操作；能预测修改后的结果，才说明开始理解其中的知识。

## 6. 收到回答后怎么做

1. 先看建议改哪些文件、为什么改；不理解命令就要求解释作用和影响。
2. 每次只执行一个明确步骤，不整段运行尚未理解的安装、删除或全局配置命令。
3. 记录实际输出，再判断是否支持 AI 的猜测。没有变化也要反馈。
4. 修好后重新运行原来的场景，再试一个边界；例如空输入、错误文件路径、窄屏。
5. 用自己的话解释原因，再独立重做一个小变化。模型说“通过”不能代替实际验收。

## 7. 三种继续追问

```text
补证据：你还需要哪条具体信息？请告诉我在哪里查看、怎样复制。

反馈失败：我执行了你建议的【步骤】，实际输出是【原文】。
原问题【仍存在 / 发生变化】。请根据这条证据调整判断，一次只改一处。

检查理解：我认为原因是【我的解释】。请指出解释中的漏洞，
再给一道只改变一个条件的小题，先等我回答，不要直接给答案。
```

如果回答开始引入框架、数据库或大量与当前任务无关的改动，可以补充：“这次只解决当前最小问题，保留已有结构；请说明哪些改动是必要的。”

## 8. 在本站怎样操作

1. 使用下方“我的问题整理器”，填入自己的六项信息。目标和实际结果必填；没有写过代码或没有尝试就明确填写“尚未写代码”“还没尝试”。
2. 点击“生成我的提问”，检查整理结果；看到“待补充”时回到对应字段填写，再重新生成。本站只整理文字，此时不会出现 AI 回答。
3. 点击“复制我的提问”。若浏览器不允许自动复制，选中结果文字，按 `Ctrl+C`（Mac 为 `Cmd+C`）或使用复制菜单。
4. **保留本站标签页**，另开浏览器标签页进入你平时使用的 AI 工具官方网页或应用，按该工具要求登录。在其聊天输入框粘贴（`Ctrl+V` / `Cmd+V`），检查无隐私信息后由你自己点击发送。第一次使用时确认服务是否可用及其费用规则；无需为了本教程安装桥接扩展、购买 API Key 或使用 VS Code 内置 AI。
5. 把 AI 给的一个检查步骤带回 VS Code，先理解，再执行；将实际结果粘贴回**同一个对话**。未解决就用上面的“反馈失败”模板继续，解决后重做原场景并解释原因。

还没有入口时，可从 [DeepSeek 官方网站](https://www.deepseek.com/) 的对话入口，或 [豆包官方网页](https://www.doubao.com/) 开始；已有网页版 AI 就用熟悉的那一个，只需选一个。登录方式、可用地区与额度以服务当时页面为准。没有可用账号时，先把问题保存为笔记，也可交给老师或同学排查。本教程练习的是组织证据，提问文字本身不等于已发送或已解决。

整理器不调用模型、不伪造回复，也不会更新课时完成状态。字段只保留在当前标签页会话，切换本站教程仍可继续填写；**刷新或关闭前请复制到自己的笔记**。

课内也可打开“AI 助教”，按需勾选课程与代码，先查看上下文再整理问题。未连接扩展时只生成文字；已连接官网桥接扩展时，发送前查看完整提示词与所选官网服务。

**给自己一个小练习**：把“网页出错了，帮我改”改写成一份包含六项证据的提问。检查其中哪些是真实观察，哪些只是自己的猜测；猜测要明确写出来。
